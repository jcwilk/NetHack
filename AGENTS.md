# NetHack – Agent Guide

This project is NetHack 3.6.7 configured to run from the build directory (playground mode). This guide explains how agents can run, interact with, and debug the game.

## Project Overview

- **NetHack**: Classic roguelike dungeon crawler (C, curses UI)
- **Playground mode**: Game runs from source tree; data and saves live in `dat/`
- **Key scripts**: `start.sh` (run game), `agent_start.sh` (run + capture for agents), `agent_stop.sh` (kill game)
- **Build**: `make all` from project root; `Makefile` is generated by `sys/unix/setup.sh`

## Running and Interacting with the Game

### Human use

```bash
./start.sh
```

### Agent use (capture output, send keypresses)

```bash
./agent_start.sh &                    # Start in background
cat agent_screen_dump.txt             # Read current screen (updated ~1s)
echo -n ' ' > agent_keypress.txt      # Send space key
# ... react to output, send more keypresses ...
wait                                  # Wait for game to exit
```

### Stopping the game

```bash
./agent_stop.sh                       # Kill via pidfile when no clean exit path
```

## How agent_start.sh Works

1. **Pipeline**: A loop feeds keypresses into `script(1)`’s stdin; `script` forwards them to the game’s PTY.
2. **Screen dump**: The loop copies `agent_session.log` into `agent_screen_dump.txt` about once per second (with ANSI escapes stripped).
3. **Keypresses**: Writing to `agent_keypress.txt` causes the loop to send that content to the game.
4. **No timeout**: The game runs until it exits or is stopped.

**Files:**

| File                  | Purpose                                      |
|-----------------------|----------------------------------------------|
| `agent_screen_dump.txt` | Current screen (read)                       |
| `agent_keypress.txt`   | Keypresses to send (write)                  |
| `agent_pidfile`        | PID of the script process (for `agent_stop`) |
| `agent_session.log`    | Raw captured session                        |

**Environment variables** (optional): `AGENT_LOGFILE`, `AGENT_SCREEN_DUMP`, `AGENT_KEYPRESS`, `AGENT_PIDFILE`

## How agent_stop.sh Works

Reads the PID from `agent_pidfile`, sends `SIGTERM` to that process, then removes the pidfile. Use when the game is stuck or there is no obvious way to exit via keypresses.

## Dev Loop: Change Code → Test → Debug

1. **Edit source** in `src/`, `include/`, `dat/`, etc.
2. **Rebuild**: `make all` (or let `start.sh` / `agent_start.sh` run it)
3. **Run via agent**:
   ```bash
   ./agent_start.sh &
   ```
4. **Inspect output**:
   ```bash
   cat agent_screen_dump.txt
   ```
5. **Send input** when the game is waiting (e.g. “Hit space to continue”):
   ```bash
   echo -n ' ' > agent_keypress.txt
   ```
6. **Stop if needed**:
   ```bash
   ./agent_stop.sh
   ```

## Common Issues

- **“Cannot open file perm”**: Create `dat/perm`, `dat/record`, `dat/logfile`, `dat/xlogfile` (e.g. `touch dat/perm dat/record dat/logfile dat/xlogfile`). `start.sh` has a commented-out line for this.
- **“Terminal must backspace”**: `agent_start.sh` sets `TERM=xterm`; do not override it.
- **“You must play from a terminal”**: The game needs a PTY. Use `agent_start.sh` (which uses `script`) instead of running the binary directly with redirected stdin.

## Code Style and Conventions

- C style: K&R; see existing sources in `src/` and `include/`
- Do not edit generated `Makefile`; change hints in `sys/unix/hints/` and rerun `setup.sh`
- Pass all arguments through to the nethack executable; do not parse or filter them in scripts
